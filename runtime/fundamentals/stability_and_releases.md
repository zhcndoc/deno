截至 Deno 1.0.0，`Deno` 命名空间 API 是稳定的。这意味着我们将努力使在 1.0.0 下工作的代码在未来的版本中继续正常运行。

## 发布计划、渠道和长期支持

Deno 每 12 周发布一个新的稳定小版本（例如 v2.1.0，v2.0.0）。

补丁发布包括对最新小版本的bug修复，按需发布 - 您可以期待在新小版本发布前有几个补丁发布。

### 发布渠道

Deno 通过四个发布渠道进行分发。每个渠道都是独立的版本线，拥有自己的“最新”版本和下载位置，因此沿着一个版本线前进不会影响其他版本线：

- `stable` - 如上所述的 SemVer 次版本/补丁版本发布。这是**默认**渠道，推荐大多数用户使用。稳定版构建从 [GitHub releases](https://github.com/denoland/deno/releases) 下载。
- `lts` - 长期支持：仅接收向后兼容的错误修复的单一稳定次版本线，推荐不希望频繁升级的企业用户使用。请参阅[长期支持](#long-term-support-(lts))。
- `rc` - 即将发布的 SemVer 次版本的候选版本。
- `canary` - 每天会多次变更的不稳定构建，因此您可以在最新错误修复和特性进入 `stable` 之前进行体验。

在大版本预发布周期（例如 3.0）期间，Deno 还会发布 `alpha` 和 `beta` 渠道。除了 `stable` 之外的所有渠道都通过 Deno 的下载服务器 `dl.deno.land` 提供。

### 选择渠道

您安装的 Deno 恰好属于一个渠道，该渠道会在构建二进制文件时嵌入其中。`deno upgrade` 会读取当前二进制文件所属的渠道，以决定“最新”所指的内容；您偶尔看到的更新通知也基于同样的信息。例如，LTS 二进制文件会打印
`A new LTS release of Deno is available`，并告诉您运行
`deno upgrade lts`。

版本号本身无法标识渠道。同一版本可能以两个字节不同的构建形式发布：例如，`2.9.3` 同时存在稳定版和 LTS 版。它们由相同的源代码构建，并携带相同的版本字符串，区别仅在于嵌入的渠道标记以及下载位置不同。无法通过版本号请求“2.9.3 的 LTS 构建”，因为两个版本的版本字符串相同。您应根据渠道而不是版本来选择构建，而单独使用版本号时始终会解析为 **stable** 构建。

| 命令                      | 解析为                                  | 生成的构建 |
| ------------------------- | --------------------------------------- | ---------- |
| `deno upgrade`             | 最新的 **stable** 版本                  | stable     |
| `deno upgrade 2.9.3`       | **stable** 渠道上的 2.9.3 版本           | stable     |
| `deno upgrade lts`         | 最新的 **lts** 版本                      | lts        |
| `deno upgrade rc`          | 最新的 **rc** 版本                       | rc         |
| `deno upgrade canary`      | 最新的 canary 构建                       | canary     |
| `deno upgrade <git-hash>`  | 指定的 canary 构建                       | canary     |

若要有意切换渠道，请传入渠道名称，例如
`deno upgrade lts` 或 `deno upgrade stable`。由于单独使用版本号始终会选择稳定版构建，因此 LTS 用户运行 `deno upgrade 2.9.3` 时，会下载稳定版构建，并从 `lts` 渠道切换到 `stable`。若要继续使用 LTS，请使用 `deno upgrade lts` 进行升级。

渠道名称始终会解析为该渠道的最新构建，因此
`deno upgrade lts` 会安装最新的 LTS 版本，并且不存在可以固定到旧版 LTS 补丁版本的 `deno upgrade` 形式。版本号只能选择稳定版（或 `rc`、`alpha`、`beta`）构建，绝不会选择 LTS 构建。更多信息请参阅
[`deno upgrade`](/runtime/reference/cli/upgrade/)。

### 长期支持 (LTS)

Deno 提供 LTS（长期支持）渠道：一条仅通过向后兼容的错误修复进行维护的稳定次版本线。该渠道面向希望保持在同一发布线、不引入新特性或破坏性变更的企业用户。使用 `deno upgrade lts` 安装或更新。

LTS 渠道目前处于 Deno 2.9 版本线，从 **v2.9.3** 开始，并维护至 2027 年 1 月 31 日。

| LTS 发布版本 | LTS 维护开始时间 | LTS 维护结束时间 |
| ------------------- | --------------------- | ------------------- |
| v2.1                | 2025 年 2 月 1 日         | 2025 年 4 月 30 日      |
| v2.2                | 2025 年 5 月 1 日         | 2025 年 10 月 31 日      |
| v2.5                | 2025 年 11 月 1 日         | 2026 年 4 月 30 日      |
| v2.9                | 2026 年 7 月 1 日         | 2027 年 1 月 31 日      |

LTS 支持窗口刚开始时较短，我们计划在将来将该支持窗口延长至一年。**LTS 发布每六个月进行一次**，根据需要提供补丁发布以修复 bug。

LTS 覆盖范围包括：

- 安全补丁
- 关键bug修复（例如，崩溃、错误计算）
- **关键**性能改进_可能_根据严重性进行回溯。

**API 更改和重大新特性将不会进行回溯。**

## 不稳定的 API

引入新 API 时，这些 API 首先被标记为不稳定。这意味着该 API 未来可能会发生变化。在显式传递不稳定标志（如 `--unstable-kv`）之前，这些 API 并不可用。
[了解有关 `--unstable-*` 标志的更多信息](/runtime/reference/cli/unstable_flags)。

还有一些被视为不稳定的非运行时功能，这些功能被锁定在不稳定标志后面。例如，`--unstable-sloppy-imports` 标志用于在不指定文件扩展名的情况下启用代码的 `import`。

## 标准库

Deno 标准库 ([https://jsr.io/@std](https://jsr.io/@std)) 基本上是稳定的。所有版本为 1.0.0 或更高的标准库模块被视为稳定。所有其他模块（0.x）被视为不稳定，未来可能会发生变化。

不推荐在生产代码中使用不稳定的标准库模块，但这是实验新特性并向 Deno 团队提供反馈的好方法。使用不稳定标准库模块不需要使用任何不稳定标志。
